# DotsAndBoxes — короткий roadmap после стабилизации

Дата: 27 октября 2026. План не реализован в этой задаче.

| Очередь | Маленькая задача | Проверяемый результат | Зависимости / риск |
| --- | --- | --- | --- |
| P0 | Ротация раскрытого токена владельцем, затем отдельная очистка tracked `.env` | Новый секрет только в runtime; старый отозван; clean checkout проходит офлайн-тесты | BotFather/deployment только владельцем; историю не переписывать без отдельного решения |
| P1 | Smoke отдельного тестового бота | Два тестовых аккаунта проходят PvE/PvP/replay/leave; проверен фактический classic 4×4 | Только после ревью PR; runtime UX сейчас не проверен |
| P1 | Согласовать AFK-правила и добавить один реальный scheduler-путь | На captured turn version один timeout; старый job ничего не меняет; тесты double timeout, reconnect, конец, повторный callback | Решить, кого заменяет bot, можно ли вернуть игрока, что значит surrender и кто выигрывает. Начать с таймера и одного согласованного сценария |
| P2 | Явный TTL очереди и abandoned active-комнаты | Один согласованный срок, уведомление участников, cleanup не затрагивает новые матчи | Не вводить произвольный 30-минутный abort; сначала продуктовые правила |
| P2 | AI: маленький benchmark и улучшение Hard | Детерминированный набор endgame-позиций и head-to-head со старым ботом; измеримые win rate/latency | Текущий Hard — эвристика; не обещать оптимальную игру. Не менять правила захвата |
| P2 | Статистика завершённых матчей | Одна идемпотентная запись на match ID; ничья/выход явно классифицированы; повторный callback не добавляет победу | Согласовать приватность и хранение; отдельная миграция/rollback только при выборе БД |
| P3 | Серии, достижения и профиль | 2–3 понятных достижения из проверенной истории; пересчёт не удваивает награды | После достоверной статистики, без большой системы экономики |
| P3 | PvP рейтинг | Отдельный рейтинг world-PvP; один матч — одно изменение; тест ничьи/повтора/сдачи | После идемпотентной статистики; решить anti-farming и поведение friend-матчей |
| P2/P3 | UX и визуализация | Выбрать одно улучшение: например edit вместо удаления своего поля или яснее очередь/страницы; ручная проверка двух клиентов | Сохранить темы и меню; не превращать в WebApp |
| По необходимости | Персистентность матчей | Restart восстанавливает одну партию, версии и участников; stale callback после restart отвергается | Сначала доказать потребность. Для одного процесса оценить snapshot/SQLite; Redis/PostgreSQL не вводить по умолчанию |

Рекомендуемый следующий шаг: review текущего PR, ротация токена владельцем и короткий smoke изолированного тестового бота. Затем выбрать **одну** следующую игровую возможность.
